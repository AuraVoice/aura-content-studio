# Automated Short-Form Video Publishing APIs and AI-Content Labeling Rules (as of October 2026)

Research method note: in this session the official developer doc hosts (developers.facebook.com, developers.tiktok.com, developers.google.com) could not be fetched directly (blocked by the session network allowlist). Facts below come from web search result summaries of those official pages plus third-party developer guides. Where a claim rests only on a vendor or SEO blog it is flagged. Anyone finalizing the architecture should open the official reference pages once those domains are allowed.

## Instagram Graph API: Content Publishing for Reels

### Takeaway
Reels publishing is a two-step container flow (create container with `media_type=REELS`, poll `status_code` until `FINISHED`, then publish), now available through "Instagram API with Instagram Login" using the `instagram_business_content_publish` permission. The rolling 24-hour cap is reported as 50 API posts on the current Meta page (older pages say 100 or 25), so query `content_publishing_limit` rather than hardcoding; one post per day is nowhere near the cap.

### Cited Findings
- Publishing is two steps; check `GET /{CONTAINER_ID}?fields=status_code`, whose values are `IN_PROGRESS`, `FINISHED`, `ERROR`, `EXPIRED`, `PUBLISHED`. Do not publish until `status_code` is `FINISHED` - [Meta Content Publishing docs](https://developers.facebook.com/docs/instagram-platform/content-publishing/) (via search summary)
- To publish a reel, follow the single-media steps and include `media_type=REELS` - [Meta Content Publishing docs](https://developers.facebook.com/docs/instagram-platform/content-publishing/) (via search summary)
- Rate limit conflict: the current Meta instagram-platform page reportedly says accounts are limited to 50 API-published posts in a rolling 24 hours; older Meta pages say 100; some third-party sources say 25. Check live value via `GET /{ig-user-id}/content_publishing_limit` - [Meta Content Publishing docs](https://developers.facebook.com/docs/instagram-platform/content-publishing/); [Meta legacy content publishing guide](https://developers.facebook.com/docs/instagram-api/guides/content-publishing/); [Ayrshare on Error 9 / 25-post limit](https://www.ayrshare.com/solutions/instagram-graph-api-error-9-the-25-post-daily-limit-how-to-fix-it/); [Upload-Post Instagram API guide 2026](https://www.upload-post.com/instagram-api/)
- An unpublished container expires if not published within 24 hours - [bundle.social Instagram Graph API production guide](https://bundle.social/blog/instagram-graph-api) (third-party)
- Permission for Instagram Login is `instagram_business_content_publish`, served from `graph.instagram.com`; Meta ties Instagram Login publishing to Advanced or Standard Access - [Meta Content Publishing docs](https://developers.facebook.com/docs/instagram-platform/content-publishing/) (via search summary)
- Account type conflict: one guide says Reels publishing works only with Business accounts; another says Business or Creator accounts. Not resolved against Meta's own text in this session - [PostProxy Instagram Reels API guide](https://postproxy.dev/blog/instagram-reels-api-publishing-guide/); [bundle.social Instagram reference](https://info.bundle.social/api-reference/platforms/instagram)
- Trial Reels: add a `trial_params` object to the Reel container request; Meta's example uses `graduation_strategy: "MANUAL"`; the other value is `SS_PERFORMANCE` (auto-graduate on performance, per a third-party paraphrase). Graduation itself is not exposed by the API and must be done in the Instagram app - [Meta Content Publishing docs](https://developers.facebook.com/docs/instagram-platform/content-publishing/); [Sume trial Reels guide](https://www.sume.com/guides/instagram-trial-reels-api-graduation-strategy); [Ayrshare Instagram API docs](https://www.ayrshare.com/docs/apis/post/social-networks/instagram)
- Collaborators can be added to Reels, images and carousels, capped at three usernames - [SocialAPI Instagram publishing docs](https://docs.social-api.ai/platforms/instagram/publishing) (third-party)
- Custom cover: `cover_url` (external image URL) or `thumb_offset`; if neither is set Instagram picks a frame; `cover_url` wins when both are set - [PostProxy Instagram Reels API guide](https://postproxy.dev/blog/instagram-reels-api-publishing-guide/) (third-party)
- AI label via API: Ayrshare documents that setting `isAIGenerated: true` in `instagramOptions` adds Instagram's "AI info" label; Ayrshare does not detect AI content itself; labels cannot be changed after posting; non-boolean values publish without the label and return warning code 497 - [Ayrshare Instagram API docs](https://www.ayrshare.com/docs/apis/post/social-networks/instagram); [Ayrshare latest updates](https://www.ayrshare.com/docs/whatsnew/latest)

### Inferences
- Because Ayrshare can set Instagram's AI info label through its API, Meta very likely exposes a native container parameter for AI disclosure; the native field name was not confirmed in this session.
- For a single creator posting to their own account, Standard Access (app in development mode, the creator's account holding a role on the app) may be enough and avoid full App Review; this needs confirming in Meta's access-level docs.
- On Vercel, the container polling step should not block a single serverless invocation: create the container, persist the container id (Supabase / LangGraph checkpoint), and poll from a scheduled job or a resumed graph step, publishing well inside the 24-hour container expiry.
- The video must sit at a publicly reachable `video_url` (e.g. a signed Supabase Storage URL) for Meta to pull it.

### Gaps
- Exact current video specs for API Reels (max duration via API, max file size, codec) were not retrieved from Meta's page.
- Exact native API field name for the AI label on Instagram containers (Ayrshare's wrapper name is `isAIGenerated`).
- Whether `share_to_feed`, `audio_name`, `user_tags`, `location_id` are still valid on Reels containers in 2026 was not verified.
- Whether Creator accounts (vs Business only) can publish Reels via Instagram Login: sources conflict.

## TikTok Content Posting API

### Takeaway
Unaudited apps can only post privately (`SELF_ONLY`), to private accounts, with at most 5 users per 24 hours; public Direct Post requires passing TikTok's audit, which reportedly takes from several days up to about six weeks with multiple rejections common. The API exposes `post_info.is_aigc` (boolean) that applies the "Creator labeled as AI-generated" tag, and requires a `creator_info` query to render the posting UI before every post.

### Cited Findings
- Unverified developers can use the API, but all content uploaded through it is restricted to private viewing; lifting this requires an audit of the API client - [TikTok Content Sharing Guidelines](https://developers.tiktok.com/doc/content-sharing-guidelines/) (via search summary)
- Unaudited clients: up to 5 users posting in a 24-hour window, and all posting accounts must be set to private at time of posting - [TikTok Content Sharing Guidelines](https://developers.tiktok.com/docs/en/content-sharing-guidelines) (via search summary)
- Per-creator cap: a limit on Direct Post posts per creator account per 24 hours, "typically around 15 posts per day/creator account", shared across all API clients using Direct Post; applies to audited and unaudited clients - [TikTok Content Sharing Guidelines](https://developers.tiktok.com/doc/content-sharing-guidelines/) (via search summary)
- Clients must query creator info to render UI elements on the export page before calling the posting API, and retrieve the latest creator info when rendering the "Post to TikTok" page - [TikTok photo post reference](https://developers.tiktok.com/doc/content-posting-api-reference-photo-post); [TikTok Content Sharing Guidelines](https://developers.tiktok.com/doc/content-sharing-guidelines/)
- Before audit, `privacy_level` is forced to `SELF_ONLY` regardless of selection (Postiz self-host docs) - [Postiz TikTok provider docs](https://docs.postiz.com/self-host/providers/tiktok)
- Posting to a public account from an unaudited app returns `unaudited_client_can_only_post_to_private_accounts` (HTTP 403) on init - [PostZen TikTok API errors](https://www.postzen.dev/blog/tiktok-content-posting-api-errors) (third-party)
- `post_info.is_aigc` is a boolean; `true` labels the video as AI-generated ("Creator labeled as AI-generated") - [TikTok Direct Post reference](https://developers.tiktok.com/docs/en/content-posting-api-reference-direct-post) (via search summary); [AdaptlyPost TikTok AI label](https://adaptlypost.com/blog/tiktok-ai-generated-label)
- `is_aigc` sits in `post_info` for video and top level for photo posts; the inbox (Upload/draft) endpoint has no such field - [AdaptlyPost TikTok AI label](https://adaptlypost.com/blog/tiktok-ai-generated-label) (third-party, not confirmed on official page)
- Direct Post UX must match TikTok's guidelines: privacy selector, creator info display, and commercial-content disclosure - [TikTok Content Sharing Guidelines](https://developers.tiktok.com/doc/content-sharing-guidelines/); [bundle.social TikTok API approval](https://bundle.social/blog/tiktok-api-approval)
- Audit duration: TikTok FAQ reportedly says several days to two weeks; third parties report 2 to 4 weeks with multiple feedback rounds, about three weeks with at least one rejection, six weeks and more than a dozen submissions (PostZen), and about two weeks (Breakreach, filed 5 Sep 2026, approved 18 Sep 2026) - [PostPeer TikTok posting API 2026](https://www.postpeer.dev/blog/best-tiktok-posting-api); [PostZen TikTok API guide](https://www.postzen.dev/blog/tiktok-api); [Breakreach TikTok API](https://www.breakreach.com/developers/tiktok-api); [Postwire TikTok approval](https://postwire.io/platforms/tiktok/approval/)
- Common rejection causes: website and posting UI, not the API calls - [bundle.social TikTok API approval](https://bundle.social/blog/tiktok-api-approval); [Postwire TikTok approval](https://postwire.io/platforms/tiktok/approval/)
- Ayrshare exposes `tikTokOptions.isAIGenerated` (video only) and quotes TikTok: turning on the AI-generated setting "won't affect the distribution of your video as long as it doesn't violate TikTok's Community Guidelines" - [Ayrshare TikTok API docs](https://www.ayrshare.com/docs/apis/post/social-networks/tiktok)

### Inferences
- The Telegram approval step maps naturally onto TikTok's required UX: the approval message in Telegram (or a small web page linked from it) should show creator_info (nickname, allowed privacy levels, interaction toggles) and let the creator pick privacy and confirm, because the audit reviews that UI.
- If the team will not build and audit its own TikTok app, a hosted unified API that is already audited (Ayrshare, Upload-Post, Zernio) avoids the audit; self-hosted Postiz does not, since its own docs show `SELF_ONLY` until your app is audited.
- One post per day is well under the ~15/day creator cap.
- Use Direct Post (not inbox/Upload) if the AI label must be set by API, since the inbox endpoint reportedly lacks `is_aigc`.

### Gaps
- Exact `source_info` options (`FILE_UPLOAD` vs `PULL_FROM_URL`) and the URL-prefix/domain verification rule for `PULL_FROM_URL` were not confirmed this session.
- Per-endpoint request rate limits (requests per minute per token) not retrieved.
- Full list of `post_info` fields (`disable_duet`, `disable_stitch`, `disable_comment`, `video_cover_timestamp_ms`, `brand_content_toggle`, `brand_organic_toggle`) not confirmed from the official page.

## YouTube Data API v3 (Shorts upload)

### Takeaway
Since a reported 1 June 2026 change, `videos.insert` has its own bucket of 100 calls per day (1 unit each) instead of costing ~1,600 units from the 10,000-unit pool; Google's own audit page confirms a default of 100 `videos.insert` calls per day. There is no Shorts flag: a vertical or square video up to 3 minutes is classified as a Short. `status.containsSyntheticMedia` (since 30 Oct 2024) sets the altered/synthetic disclosure on `videos.insert` and `videos.update`.

### Cited Findings
- Default allocation: 100 `search.list` calls, 100 `videos.insert` calls, and 10,000 units/day for all other endpoints combined; raising quota requires the "YouTube API Services - Audit and Quota Extension Form" - [Google Quota and Compliance Audits](https://developers.google.com/youtube/data/guides/quota_and_compliance_audits) (via search summary)
- 1 June 2026: Data API moved to granular buckets; `videos.insert` and `search.list` get 100 calls/day at 1 unit per call; previously an upload cost 1,600 units from the general pool. One source says per-upload cost fell to 100 units in December 2025 first; another gives 5 October 2026 for current defaults. No official Google announcement found - [PostZen YouTube quota 2026](https://www.postzen.dev/blog/youtube-api-quota-exceeded); [Outstand YouTube API pricing](https://www.outstand.so/blog/youtube-api-pricing-quota); [Upload-Post YouTube API guide](https://www.upload-post.com/youtube-api/); [bundle.social quota guide](https://bundle.social/blog/youtube-api-quota-exceeded-limits-fixes)
- Quotas reset at midnight Pacific; `uploadLimitExceeded` (400) is a separate channel-level upload allowance - [PostZen YouTube Data API upload guide](https://www.postzen.dev/blog/youtube-data-api-upload)
- Private-upload restriction conflict: the `videos.insert` docs were quoted as saying all videos uploaded from unverified API projects created after 28 July 2020 are restricted to private viewing; a GitHub issue comment (late October 2026) claims this was dropped from current docs. Single unverified claim - [Upload-Post YouTube API guide](https://www.upload-post.com/youtube-api/); [GitHub issue igormcsouza/aurora #1](https://github.com/igormcsouza/aurora/issues/1); [Breakreach YouTube API](https://www.breakreach.com/developers/youtube-api)
- No Shorts flag or endpoint; square or vertical up to 3 minutes is filed as a Short; the 3-minute limit dates from September/October 2024 (previously 60 seconds) - [bundle.social YouTube Shorts API](https://bundle.social/blog/youtube-shorts-api-secrets); [Wikipedia YouTube Shorts](https://en.wikipedia.org/wiki/YouTube_Shorts); [VEED Shorts API](https://www.veed.io/learn/youtube-shorts-api)
- `status.containsSyntheticMedia` added 30 October 2024; settable on `videos.insert` and `videos.update`; covers making a real person appear to say/do something they did not, altering footage of real events/places, or generating realistic scenes that did not occur - [YouTube Data API revision history](https://developers.google.com/youtube/v3/revision_history) (via search summary)
- Field is only populated when the uploader sets it; older bulk tools may never send it (opinion piece) - [singhamandeep.com AI Disclosure](https://singhamandeep.com/?p=1572)

### Inferences
- One upload per day uses 1 of 100 daily `videos.insert` calls; quota is not a constraint under either the old (1,600 of 10,000 units) or new model.
- Always send `status.containsSyntheticMedia: true` and an explicit `status.privacyStatus` on insert, then read back the video resource to confirm privacy status; if it comes back `private`, the project is hitting the unverified-project restriction and needs the compliance audit.
- Resumable upload of a large file from a Vercel function risks timeouts; stream from storage in a background job or use a unified API.

### Gaps
- OAuth consent-screen verification requirements for the `youtube.upload` scope were not confirmed this session. Prior knowledge (unverified here): apps left in "Testing" publishing status issue refresh tokens that expire after 7 days, which would break a daily unattended upload; verify in Google Cloud docs.
- Current status of the post-2020 unverified-project private restriction (sources conflict).

## Facebook Reels API (Page `video_reels` endpoint)

### Takeaway
Facebook Reels publish only to Pages (not personal profiles) via `POST /{page_id}/video_reels`, capped at 30 API-published Reels per rolling 24 hours per Page, 3 to 90 seconds, 9:16. The 90-second cap is the tightest duration limit of the four platforms.

### Cited Findings
- "Reels API is limited to 30 API-published posts within a 24-hour moving period", enforced on `POST /{page_id}/video_reels`; Meta recommends the app also enforce it - [Meta Reels Publishing API](https://developers.secure.facebook.com/documentation/video-api/guides/reels-publishing) (via search summary)
- Specs: 3 to 90 seconds (60 s when published as a Page story); 9:16; 1080x1920 recommended, minimum 540x960; 24 to 60 fps; audio 128 kbps+, stereo, AAC, 48 kHz - [Meta Reels Publishing API](https://developers.secure.facebook.com/documentation/video-api/guides/reels-publishing) (via search summary)
- Conflicts: some guides say minimum 720p; one says max API file size 300 MB; one says scheduled Reels need publish time more than 10 minutes out and within 29 days. Not confirmed in Meta docs - [Reel Uploader FB Reels specs](https://reeluploader.com/blog/facebook-reels-specs); [VideoToolery FB video limits](https://videotoolery.com/blog/facebook-video-size-limits); [PostEverywhere FB API guide](https://posteverywhere.ai/blog/post-to-facebook-api)
- "Meta publishes Reels to Pages only"; personal profiles not reachable via official API - [Apify Social Media Uploader Pro](https://apify.com/dami_studio/social-media-uploader-pro) (third-party)

### Inferences
- Target video length of 90 seconds or less satisfies Facebook Reels, YouTube Shorts (3 min), and Instagram/TikTok, so a single master render can serve all four.
- The creator needs a Facebook Page; Page token with publishing permissions (likely `pages_manage_posts`, `pages_read_engagement`, `pages_show_list`) is required.

### Gaps
- Exact permissions and the three-phase upload flow (`upload_phase=start`, upload to `rupload.facebook.com` with `file_url` or binary, `upload_phase=finish` with `video_state=PUBLISHED`) were not confirmed from Meta's page this session.
- No source found on API-level crossposting of an Instagram Reel to Facebook (or vice versa); treat as two separate publishes.
- AI label via the Facebook Reels API: no source found.

## Platform AI-Generated Content Policies (2026)

### Takeaway
All three platform families require disclosure of realistic AI-generated people or voices and also auto-label from C2PA/IPTC metadata; on TikTok an auto-label cannot be removed. Disclosure itself does not reduce reach or monetization per TikTok and YouTube statements; YouTube's risk for a daily AI-avatar channel is the "inauthentic content" policy (renamed from "repetitious content" on 15 July 2025) aimed at mass-produced, templated content.

### Cited Findings
- Meta (Feb 2024 announcement): detects C2PA and IPTC "AI generated" markers and added a self-disclosure option for AI video and audio - [AlternativeTo Meta labeling news (2024)](https://alternativeto.net/news/2024/2/meta-will-start-labeling-ai-generated-content-across-facebook-instagram-and-threads); [Versely how Meta decides](https://www.versely.studio/blog/how-meta-decides-to-show-an-ai-label)
- Meta: realistic AI video and audio must be labeled by the user; AI images need not be; photorealistic video and realistic audio require user disclosure - [SignUnder Meta labels](https://signunder.com/labels/meta); [ai-label.app Meta](https://www.ai-label.app/en/platforms/meta/) (third-party)
- Meta label naming conflict: renamed "Made with AI" to "AI info" in 2024; some 2026 sources say Instagram now shows "AI content" - [PrivyClean Instagram AI label](https://www.privyclean.app/instagram-ai-label); [Versely labeling guide](https://www.versely.studio/blog/how-to-label-ai-on-instagram)
- Meta: switching off the disclosure toggle reportedly does not stop a metadata-triggered label - [PrivyClean Instagram AI label](https://www.privyclean.app/instagram-ai-label) (third-party)
- Meta: an "AI-generated profile" toggle reportedly replaced "AI creator" on 31 August 2026 (single source) - [Versely how Meta decides](https://www.versely.studio/blog/how-meta-decides-to-show-an-ai-label); see also [CreatorLane Instagram AI creator label 2026](https://creatorlanehq.com/blog/instagram-ai-creator-label-2026)
- TikTok: visible label required for AI visuals/audio depicting realistic people or scenes; AI content is allowed, the policy governs disclosure - [Storrito TikTok labeling rules](https://storrito.com/resources/tiktoks-2026-ai-labeling-rules-and-what-they-signal-for-platform-governance/); [CineRads TikTok AI policy](https://www.cinerads.com/blog/tiktok-ai-content-policy) (third-party)
- TikTok: requirement covers AI avatars, voices and manipulated visuals that look like a real person; a creator using an AI avatar for a personal vlog needs the same label as a paid AI product demo - [Pixo TikTok AI label compliance](https://pixo.video/blog/tiktok-ai-label-compliance-guide); [HypeLive TikTok AI rules 2026](https://www.hypelive.io/en/blog/tiktok-ai-content-rules-2026) (third-party)
- TikTok: reads C2PA Content Credentials and auto-labels; start date conflict (May 2024 vs January 2025); auto-labels cannot be removed; auto-detection not universal for content made outside TikTok - [Billo platform AI labeling](https://billo.app/blog/ai-labeling/); [AdaptlyPost TikTok AI label](https://adaptlypost.com/blog/tiktok-ai-generated-label); [Denver7 (2024) TikTok begins labeling](https://www.denver7.com/science-and-tech/social-media/tiktok-begins-labeling-ai-generated-content)
- TikTok: 21 July 2026 ad-policy update reportedly mandates labels on all AI content in ads (unconfirmed against official TikTok source) - [CommonThread TikTok AI ad rules](https://commonthreadco.com/blogs/coachs-corner/tiktok-ai-ad-disclosure-rules-ecommerce-2026)
- YouTube: creators must label realistic altered/synthetic content (e.g. a real person appearing to say something they never said) via the "Altered or synthetic content" toggle; YouTube adds a description disclosure and a player label for photorealistic content - [air.io YouTube AI disclosure 2026](https://air.io/en/youtube-hacks/youtube-ai-disclosure-in-2026-label-it-yourself-or-youtube-will); [Layer3 Labs YouTube AI policy](https://www.layer3labs.io/guides/youtube-ai-content-policy)
- YouTube: disclosing "won't limit a video's audience or impact its eligibility to earn money"; non-disclosure can lead to removal or YPP suspension - [air.io YouTube AI disclosure 2026](https://air.io/en/youtube-hacks/youtube-ai-disclosure-in-2026-label-it-yourself-or-youtube-will); [TrezaLabs YouTube AI monetization](https://www.trezalabs.com/blog/youtube-ai-content-monetization-policy)
- YouTube: "inauthentic content" policy renamed from "repetitious content" 15 July 2025; targets mass-produced, low-effort, templated content replicable at scale, not AI per se; AI personas presented as human experts on health, legal, financial or political topics flagged as monetization risk - [LensPOV YouTube inauthentic policy](https://lenspov.com/articles/youtube-ai-content-demonetization-2026); [arwriterai inauthentic policy 2026](https://arwriterai.com/en/blog/youtube-inauthentic-content-policy-ai-creators-2026/); [air.io monetization timeline](https://air.io/en/monetization/youtube-monetization-policy-changes-2026-a-complete-dated-timeline)
- YouTube enforcement: January 2026 wave deleting 16 channels with 4.7 billion combined views; enforcement reportedly at channel level; reported July 2026 clarifications not verified against YouTube help pages - [air.io monetization timeline](https://air.io/en/monetization/youtube-monetization-policy-changes-2026-a-complete-dated-timeline); [UpTube 2026 policies](https://www.uptube.io/blog/youtube-new-policies-2026)

### Inferences
- An AI avatar clone of the creator speaking a script they never physically recorded is "realistic synthetic content depicting a real person" on all three platforms and should be labeled every time: `is_aigc: true` on TikTok, `containsSyntheticMedia: true` on YouTube, and the Meta AI label on Instagram/Facebook. Labeling has no documented reach penalty; not labeling risks removal or strikes.
- If the generator (e.g. Higgsfield) embeds C2PA, TikTok and Meta will likely auto-label regardless, so the pipeline should not try to strip metadata; set the label explicitly so it is consistent.
- For YouTube, a daily templated AI-avatar Shorts format is the main policy risk (inauthentic/mass-produced); varying scripts, visible human creative input, and avoiding expert-advice framing reduce it. Monetization may matter less for a marketing channel, but channel-level enforcement can remove the channel.

- Whether YouTube's disclosure rules explicitly exempt a creator's own consented AI likeness was not found.

## Legal and Likeness: AI Clone of Yourself (FTC, ASCI/India, EU AI Act Article 50)

### Takeaway
EU AI Act Article 50 deepfake disclosure duties for deployers apply from 2 August 2026 with no delay; only the provider-side machine-readable watermarking duty got a grace period to 2 December 2026 for systems already on the market. India's amended IT Rules (notified 10 February 2026) make platforms require user declaration and labeling of synthetic audio/video, and ASCI's September 2026 guidelines require ad labeling of synthetic influencers/ambassadors where material to consumers. FTC Endorsement Guides apply to virtual influencers; no standalone FTC AI-influencer rule was confirmed.

### Inferences
- An AI clone of the creator is a "deepfake" in the EU sense (realistic depiction of an existing person), so if the content reaches EU audiences, the creator/company as deployer must disclose it, from 2 August 2026. The platform AI labels plus an on-screen or caption note ("Made with an AI version of me") is the practical way to meet this. The Article 50(2) watermark is the generator vendor's job, not the publisher's.
- Aura Desktop marketing videos are advertising for the creator's own product, so ASCI's guideline is relevant if Indian audiences are targeted: an AI avatar of the founder is a "synthetic ambassador" and should carry a clear label. The IT Rules mean Indian-facing platforms will ask for a declaration at upload; the API AI flags are how an automated pipeline answers that.
- Under FTC rules, self-promotion of one's own product carries an obvious connection, but the avatar must not claim personal experiences that did not happen, and product claims must stay within `src/lib/product.ts`.
- Consent to one's own likeness is not an issue for a self-clone; the remaining risk is deception, which consistent labeling addresses.
